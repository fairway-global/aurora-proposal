# 2. 背景と課題

従来の融資では、すべての融資が、固有の条件、リスク特性、返済日程、決済条件を持つ特定当事者間の個別契約として始まる。各融資は、取引と同様に、組成、資金提供、管理、移転、決済を独立して行える個別の金融オブジェクトとして存在する。金融機関がそれらをポートフォリオ、ファンド、証券化商品に集約するのは、融資が成立した後である。

多くのDeFi融資プロトコルは、この順序を逆にする。まず資本を共通プールに預け入れ、借り手が事前に定められたルールに従って資金を引き出す。このモデルは一定の用途には有効だが、現実の多くの信用市場の仕組みとは異なる。

CardanoのeUTxOアーキテクチャは、個別融資を起点とするモデルに適している。取引ベースの構造により、すべての融資機会を共通の流動性プールにまとめる必要がなく、個々の金融関係を独立したオンチェーン・オブジェクトとして表現できる。

したがって、個々の融資機会は、固有の条件、状態、ライフサイクルを持つ別々の融資リクエストUTxOとして存在できる。より大きな信用ポートフォリオへ集約される前に、互換性のある融資インフラストラクチャで個別に公開、資金提供、決済できる。

これは、個々の金融契約を中心とするオープンな信用市場の技術的基礎になる。しかし、それだけでは、機関や他の資本提供者が独立した実装を横断して契約を発見、比較、評価するための共通市場基盤は生まれない。

現在、2つの問題が、個別のCardano信用機会を一貫して扱い、機関や専門的な資本提供者の業務フローで利用できるようにすることを妨げている。

## 機関に必要なのはパーミッションレスな決済だけでなく、共通市場基盤である

Cardanoの信用市場実装は、当事者が個別融資契約をオンチェーンで交渉・決済することを可能にする。しかし、機関融資者、規制対象の金融機関、専門的な資本提供者には、決済以上の機能が必要である。資本を配分する前に、融資機会を発見し、関連情報を評価し、独自の適格性・コンプライアンス要件を適用し、実績を継続的に把握するための標準化された手段が求められる。

標準化されたメタデータ、発見、フィルタリング、検証の基盤がなければ、各参加者はプロトコル固有の統合を通じて融資機会を解釈し、評価に必要な情報を個別に再構築しなければならない。

検証可能なクレデンシャル、ゼロ知識証明、その他の証明システムの進歩により、機微な元データをオンチェーンで公開することなく、機関属性、適格性、コンプライアンスなどの検証情報を機会に関連付けられる。融資プロトコルを変更するのではなく、任意の取引メタデータとオープンな検証参照によって実装すれば、基礎となる市場のパーミッションレスな利用を維持しつつ、追加の裏付けを求める参加者を支援できる。

検証は、必要な市場レイヤーの一要素である。機関には、一貫したインターフェースを通じて機会をインデックス化し、公開属性に従ってフィルタリングし、関連情報を比較し、ライフサイクルを把握する能力も必要である。

## 独立した信用市場には、個別の統合ではなく共通標準が必要である

共通標準がなければ、各融資プロトコル、アプリケーション、資本提供者が、独自のメタデータ形式、インデックス処理、発見用インターフェース、検証フロー、報告モデルを開発しなければならない。

その結果、市場情報は断片化し、統合作業が繰り返される。融資機会がオンチェーンに存在しても、実装を横断した発見や比較は難しいままとなる。資本提供者は、似たような技術統合やデューデリジェンスをプロトコルごとに行い、開発者は実質的に同じ市場機能を持つ基盤を再構築することになる。

融資モデル、法域、検証システム、資本提供者の要件が増えるほど、この断片化による負担は大きくなる。独自の発見システムは個々のアプリケーションの当面のニーズを解決できても、将来のCardano開発者が独立して採用・運用できる共通基盤にはならない。

オープン標準は、別の道を示す。共通のメタデータ標準で融資機会を一貫して記述し、共通のインデックス・発見基盤でオープンAPIを通じて公開できる。公開されたフィルタリング・検証仕様により、資本提供者や互換アプリケーションは、単一の独自市場や排他的な融資プロトコルに依存せず、各自の要件に従って機会を評価できる。

その成果は、分断された統合の集合ではなく、再利用可能な市場基盤となる。

## 2つの課題を結び付ける

Auroraは、独立した融資リクエストUTxOを取り巻く共通市場レイヤーを整備することで、両方の課題に対応する。

標準化されたメタデータにより、各機会に機械可読な市場情報と検証参照を付加する。オープンな発見・インデックス基盤が、互換性のある実装を横断してそれらを検索可能にする。資本提供者やアプリケーションは各自の要件に従って機会を発見、フィルタリング、評価でき、資金提供と決済は基礎となる融資インフラストラクチャを通じて引き続き行われる。

Auroraは融資プロトコルを置き換えず、資金提供対象を決めない。独立したCardano信用機会が一体の市場として機能するために必要なオープン標準、検証フレームワーク、発見基盤、API、開発者ツールを整備する。

トレジャリー資金により、この再利用可能な基盤を構築し、実証する。
