# 9. ガバナンスと監督

Auroraは、プロジェクトの実装にあたり、独立して管理される単一のトレジャリー資金保管構造を用いる。

配分全額の**940,000 ADA**は、独立したCardanoエコシステム代表者が管理する専用の**3-of-5 Auroraトレジャリー・マルチシグ・ウォレット**に保管する。Fairwayはプロジェクトの遂行に責任を負うが、トレジャリーの署名鍵を持たない。Sundial、Fallen Icarus、その他の実装貢献者も、資金に対する署名権限を持たない。

支出は、第7章に定める4つのマイルストーンに従って進める。Fairwayは、各累積支出上限を超えて進む前に必要な達成証拠を公開する。すべてのトレジャリー取引には、Auroraトレジャリー管理者5名のうち3名以上の承認が必要である。

## Auroraトレジャリー・マルチシグ

Auroraトレジャリー・マルチシグは、トレジャリー配分の唯一の保管ウォレットである。

すべての資金は、承認済みのプロジェクト支出に使用するまで、独立した**3-of-5マルチシグ管理**の下に置く。

実装コンソーシアムの構成員は、いずれも署名鍵を保有しない。

トレジャリー・ガバナンス上、この5名の独立したマルチシグ署名者が、共同して**Auroraトレジャリー管理者**を務める。この呼称は、別個のガバナンス機関や追加の資金保管構造を作るものではない。管理者とは、3-of-5 Auroraトレジャリー・マルチシグを管理する同じ5名を指す。

管理者は、次の責任を負う。

- トレジャリー資金の保管。
- マイルストーン達成証拠の審査。
- 承認済みのプロジェクト範囲とマイルストーン上限内での支出承認。
- 資金使用と承認済み成果物に対する進捗の監視。
- 重大な遂行上の問題が発生した場合の追加支出の停止。
- 残高と取引に関する公開の透明性の維持。
- プロジェクト終了時の未使用資金の返還。

管理者は、エンジニアリングの管理、Auroraの技術アーキテクチャの決定、実装貢献者の選定、コンソーシアム参加者間の作業分担を行わず、トレジャリー資金で開発する成果物の所有権や支配権を取得しない。

提案された取引やマイルストーンの判断に関わる重大な利益相反は、開示しなければならない。利益相反のある管理者は該当する承認に参加せず、取引は、利益相反のない署名者によって必要な3-of-5の閾値を満たさなければならない。

重大な利益相反には、提案されたトレジャリー支払いや有償のプロジェクト業務に対して直接の金銭的利害を有する場合、または雇用主、支配下の法人、密接な商業上の関係を持つ関連組織を通じて重大な間接的金銭利害を有する場合が含まれる。

管理者が辞任した場合、署名鍵にアクセスできなくなった場合、恒久的に対応不能となった場合、残る管理者は、**既存のマルチシグが引き続き3-of-5の承認閾値を満たせる場合に限り**、別の独立したCardanoエコシステム代表者への交代を承認できる。交代に新しいマルチシグ資格情報の作成が必要な場合は、同じ独立性と署名閾値を維持する代替の3-of-5 Auroraトレジャリー・マルチシグに未使用残高を移行できる。署名者の交代と新たな保管アドレスは、資金移動前に公開する。

## マイルストーンの監督

マイルストーン計画は、実装の進行に伴って承認されるトレジャリー支出の累積上限を定める。配分全額はプロジェクトを通じて同じAuroraトレジャリー・マルチシグで管理し、マイルストーンの進行に伴って別々のプロジェクトウォレット間で移動することはない。

| マイルストーン | ADA配分 |
| --- | ---: |
| M1：仕様・アーキテクチャ | **140,000** |
| M2：中核機能の構築 | **320,000** |
| M3：統合・技術デモンストレーション | **290,000** |
| M4：独立レビュー・公開 | **190,000** |
| **合計** | **940,000** |

開始時は、M1のために最大140,000 ADAの支出を承認する。M1承認後は累積上限を460,000 ADAに、M2承認後は750,000 ADAに引き上げる。M3承認後は、M4の完了に向けて全額の940,000 ADAまで使用可能となる。M4完了時に最終照合と報告を行う。

次の累積支出上限へ進む前に、以下を実施する。

1. Fairwayが、第7章で求められるマイルストーン達成証拠を公開する。
2. Auroraトレジャリー管理者が、公開された成果物を承認済みの完了基準に照らして審査する。
3. 3-of-5 Auroraトレジャリー・マルチシグによる承認を経て、次の累積支出上限に移行する。

マイルストーン審査は、証拠に基づき実務的に行う。管理者は、関連する仕様、リポジトリ、ソフトウェア、文書、実証、独立レビューの成果が公開され、承認済み完了基準を合理的に満たしていることを確認する。エンジニアリング作業の再現やAuroraの独自の再実装まで求めるものではない。

トレジャリー資金は、本提案で定義された承認済みAurora基盤の範囲とマイルストーン成果物にのみ使用できる。

## 運用責任

Fairwayは、主導実装者兼プロジェクト調整者としてAuroraの遂行に引き続き責任を負う。

実装計画、コンソーシアムの貢献、外部の技術・専門サービス、マイルストーン達成証拠、公開報告、承認済み範囲全体の遂行を調整する。

Sundialは、Aurora共通の成果物に関連する分野で技術的な実装への意見を提供する。Fallen Icarusは、基礎となる信用市場アーキテクチャや融資リクエストUTxOモデルについて、必要に応じてアーキテクチャのレビューや助言を提供できる。

これらの貢献は、1つの統合されたAurora実装の一部であり、別個のトレジャリー予算、資金保管構造、ガバナンス系統を作るものではない。

Auroraトレジャリー管理者は、資金保管、支出、マイルストーンに関する説明責任を監督するが、日々の実装作業を指揮しない。

## 透明性と報告

プロジェクト支出の開始前に、Auroraトレジャリー・マルチシグのアドレスを公開する。

すべてのトレジャリー取引は、オンチェーンで公開監査可能とする。

Fairwayは各マイルストーンにつき1件の公開進捗報告を公表する。各報告には次の内容を含める。

- 関連する公開仕様、リポジトリ、ソフトウェア、文書、レビュー資料へのリンク。
- 該当するマイルストーン完了基準に対する達成状況の要約。
- その時点までのトレジャリー支出。
- 重大な遂行上の問題や是正項目。

最終報告では、完成した資金対象の成果を承認済み提案の成果物に対応付け、最終的なオープンソース・リポジトリと文書へのリンクを提示する。

承認済みプロジェクト支出に使用する前のADAは、ステークプール運営者に委任せず、適用されるCardanoトレジャリー・ガバナンス要件に従って、定義済みの**Abstain（棄権）**投票選択肢に委任した状態を維持する。

## 返還と是正

マイルストーンが重要な点で未完了である場合、Auroraトレジャリー管理者は、Fairwayが指摘された不足に対処する間、追加のトレジャリー支出を停止できる。

目標日から**60日後**も未完了で、管理者と十分な是正計画に合意できていない場合、支出停止を継続し、下記条件に基づいてプロジェクトの終了へ進める。

完了前にプロジェクトが終了した場合、Auroraトレジャリー・マルチシグに残る未使用ADAは、適用されるトレジャリー返還手続を用いて、すべてCardanoトレジャリーに返還する。

承認済みのプロジェクト作業について正当に発生した支出は、引き続きプロジェクト支出として扱い、公開マイルストーン報告と財務照合で計上する。

個々の貢献者が変更されても、承認済みAurora成果物やFairwayの全体的な遂行責任は変わらない。
